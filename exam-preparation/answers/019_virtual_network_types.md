# Типы виртуальных сетей

## Краткий ответ
Существует несколько типов виртуальных сетей, классифицируемых по различным критериям. По режиму подключения выделяют: Bridged (мост), NAT, Host-only и Internal сети. По уровню абстракции: VLAN (802.1Q), VXLAN, overlay и underlay сети. По области применения: изолированные сети, распределенные виртуальные сети, software-defined networks (SDN), tenant networks в облачных средах. Каждый тип предназначен для решения конкретных задач и имеет свои особенности по изоляции, производительности и функциональности.

## Развёрнутый ответ

### Классификация по режиму подключения

#### 1. Bridged Network (Мост/Сетевой мост)

**Описание:**
Виртуальные машины подключаются к физической сети через виртуальный мост, становясь полноценными участниками физической сети с собственными IP и MAC-адресами.

**Характеристики:**
- Виртуальные машины получают IP-адреса из той же подсети, что и физический хост
- Прямая доступность ВМ из внешней сети
- Работа на канальном уровне (L2)
- Поддержка всех сетевых протоколов

**Применение:**
- Серверная виртуализация, где ВМ должны быть доступны как физические серверы
- Тестирование сетевых приложений в реальной среде
- Развертывание веб-серверов и других публичных служб

**Преимущества:**
- Простота интеграции с существующей инфраструктурой
- Полная функциональность сетевых протоколов
- Отсутствие дополнительных преобразований адресов

**Недостатки:**
- Требуется достаточное количество IP-адресов
- Прямая доступность из сети (требует дополнительной защиты)
- Зависимость от физической сетевой инфраструктуры

#### 2. NAT Network (Network Address Translation)

**Описание:**
Виртуальные машины используют приватную подсеть и выходят во внешнюю сеть через NAT, используя IP-адрес хоста.

**Характеристики:**
- Виртуальные машины находятся в приватной подсети (обычно 10.0.x.x или 192.168.x.x)
- Один внешний IP-адрес для всех ВМ
- Автоматическая настройка DHCP
- Работа на сетевом уровне (L3)

**Режимы работы:**
- **Shared NAT**: все ВМ используют общий NAT
- **NAT with port forwarding**: проброс портов для доступа к ВМ извне
- **Full-cone NAT**: двусторонняя трансляция для P2P приложений

**Применение:**
- Изолированные среды разработки и тестирования
- Ситуации с ограниченным количеством IP-адресов
- Дополнительная безопасность через изоляцию

**Преимущества:**
- Экономия IP-адресов
- Дополнительный уровень защиты (скрытие внутренней топологии)
- Простота настройки

**Недостатки:**
- Ограниченная доступность ВМ из внешней сети
- Необходимость настройки port forwarding для входящих соединений
- Проблемы с некоторыми протоколами (FTP, VoIP)
- Дополнительная задержка из-за трансляции адресов

#### 3. Host-only Network (Только хост)

**Описание:**
Изолированная сеть между хостом и виртуальными машинами без доступа к внешней сети.

**Характеристики:**
- Приватная подсеть, доступная только хосту и ВМ
- Нет выхода во внешнюю сеть
- Встроенный DHCP-сервер (опционально)
- Виртуальный адаптер создается на хосте

**Применение:**
- Изолированные тестовые среды
- Лабораторные работы без доступа в интернет
- Безопасный анализ вредоносного ПО
- Разработка, требующая полной изоляции

**Преимущества:**
- Полная изоляция от внешней сети
- Сохранение возможности управления с хоста
- Безопасность при работе с потенциально опасным ПО

**Недостатки:**
- Отсутствие доступа к интернету
- ВМ не могут взаимодействовать с другими физическими машинами
- Ограниченная функциональность для продуктовых сред

#### 4. Internal Network (Внутренняя сеть)

**Описание:**
Полностью изолированная сеть только между виртуальными машинами без доступа к хосту и внешней сети.

**Характеристики:**
- Изоляция даже от хостовой системы
- Связь только между ВМ в одной internal сети
- Ручная настройка IP-адресов или собственный DHCP-сервер на ВМ
- Несколько независимых internal сетей

**Применение:**
- Изолированные кластеры виртуальных машин
- Backend-сети в многоуровневых приложениях
- Тестирование распределенных систем
- Симуляция изолированных сетевых сегментов

**Преимущества:**
- Максимальная изоляция
- Множество независимых сетей
- Безопасность критичных сегментов

**Недостатки:**
- Нет доступа из хоста (усложняет управление)
- Требуется ВМ-маршрутизатор для связи с другими сетями
- Ручная настройка сети

### Классификация по технологии реализации

#### 1. VLAN (Virtual Local Area Network)

**Описание:**
Логическая сегментация физической сети на канальном уровне согласно стандарту IEEE 802.1Q.

**Характеристики:**
- Тегирование кадров для идентификации VLAN (12-bit VLAN ID, 4094 VLAN)
- Изоляция широковещательных доменов
- Работа на уровне L2
- Требует поддержки от физических коммутаторов

**Типы портов:**
- **Access port**: принадлежит одному VLAN
- **Trunk port**: передает трафик нескольких VLAN с тегами

**Применение:**
- Сегментация сети по отделам или функциям
- Изоляция трафика различных типов (data, voice, management)
- Повышение безопасности через изоляцию

**Преимущества:**
- Стандартизированная технология
- Поддержка физическим оборудованием
- Эффективная изоляция

**Недостатки:**
- Ограничение в 4094 VLAN
- Зависимость от физической инфраструктуры
- Не подходит для крупных облачных сред

#### 2. VXLAN (Virtual eXtensible LAN)

**Описание:**
Протокол overlay-сетей, инкапсулирующий L2 фреймы в UDP пакеты для передачи через L3 сеть.

**Характеристики:**
- 24-bit идентификатор (16 млн сетевых сегментов)
- Инкапсуляция в UDP (порт 4789)
- Туннелирование через IP-сети
- Виртуальные туннельные конечные точки (VTEP)

**Применение:**
- Крупные облачные инфраструктуры (AWS, Azure)
- Multi-tenant окружения
- Data center interconnect
- Overlay сети в SDN

**Преимущества:**
- Преодоление ограничения VLAN в 4094 сегмента
- Независимость от физической топологии
- Масштабируемость для облачных сред
- Поддержка L2 over L3

**Недостатки:**
- Накладные расходы на инкапсуляцию (50 байт)
- Сложность troubleshooting
- Требует поддержки от сетевого оборудования

#### 3. GRE/NVGRE Tunnels

**GRE (Generic Routing Encapsulation):**
- Универсальный протокол туннелирования
- Инкапсуляция различных протоколов в IP
- Используется для VPN и overlay сетей

**NVGRE (Network Virtualization using GRE):**
- Microsoft-реализация overlay сетей
- 24-bit Virtual Subnet ID
- Используется в Windows Server и Azure

**Применение:**
- Site-to-site VPN
- Overlay сети в гибридных облачных средах
- Hyper-V Network Virtualization

#### 4. Geneve

**Описание:**
Современный extensible протокол overlay-сетей, разработанный как эволюция VXLAN и NVGRE.

**Характеристики:**
- Гибкий формат с поддержкой метаданных
- 24-bit Virtual Network ID
- Extensible headers для дополнительной информации
- Оптимизация для NFV и SDN

**Применение:**
- Современные SDN решения
- OpenStack, Kubernetes networking
- Network Function Virtualization

### Классификация по архитектуре

#### 1. Overlay Networks

**Описание:**
Виртуальные сети, построенные поверх существующей физической инфраструктуры (underlay).

**Характеристики:**
- Логическое разделение независимо от физической топологии
- Инкапсуляция трафика
- Масштабируемость и гибкость
- Независимость от физического оборудования

**Примеры:**
- VXLAN overlay
- Kubernetes overlay networks (Flannel, Calico, Weave)
- VMware NSX overlay

**Применение:**
- Multi-tenant облачные среды
- Software-Defined Data Centers
- Container networking

#### 2. Underlay Networks

**Описание:**
Физическая сетевая инфраструктура, обеспечивающая транспорт для overlay сетей.

**Характеристики:**
- IP connectivity между хостами
- Высокая производительность
- Стабильность и надежность
- Поддержка маршрутизации

**Требования:**
- IP connectivity между всеми узлами
- Достаточная полоса пропускания
- Low latency
- Multicast поддержка (для некоторых overlay)

### Классификация по области применения

#### 1. Private Virtual Networks

**Описание:**
Изолированные виртуальные сети внутри организации или data center.

**Примеры:**
- VMware vSphere Distributed Switch
- Hyper-V Virtual Networks
- KVM/libvirt networks

**Применение:**
- Корпоративная виртуализация
- Private cloud
- Изолированные среды разработки

#### 2. Virtual Private Cloud (VPC)

**Описание:**
Изолированные виртуальные сети в публичном облаке.

**Характеристики:**
- Полная изоляция от других tenants
- Контроль IP-адресации
- Кастомизация сетевых политик
- Интеграция с on-premise сетями

**Примеры:**
- AWS VPC
- Azure Virtual Network
- Google Cloud VPC

**Применение:**
- Облачные приложения
- Hybrid cloud connectivity
- Multi-tier applications в облаке

#### 3. Software-Defined Networks (SDN)

**Описание:**
Программно-управляемые сети с разделением control plane и data plane.

**Компоненты:**
- **SDN Controller**: централизованное управление
- **Southbound API**: взаимодействие с сетевыми устройствами (OpenFlow)
- **Northbound API**: интерфейс для приложений

**Примеры:**
- OpenDaylight
- ONOS (Open Network Operating System)
- VMware NSX
- Cisco ACI

**Применение:**
- Network automation
- Dynamic traffic engineering
- Network Function Virtualization

#### 4. Container Networks

**Описание:**
Виртуальные сети, специализированные для контейнерных платформ.

**Типы:**
- **Bridge**: default Docker bridge network
- **Host**: контейнер использует сеть хоста
- **Overlay**: multi-host networking (Docker Swarm, Kubernetes)
- **Macvlan**: прямое подключение к физической сети

**CNI (Container Network Interface) плагины:**
- Flannel: простой overlay для Kubernetes
- Calico: BGP-based networking с network policies
- Weave Net: mesh overlay network
- Cilium: eBPF-based networking и security

**Применение:**
- Kubernetes cluster networking
- Docker multi-host networking
- Microservices communication

### Специализированные типы

#### 1. Service Mesh Networks

**Описание:**
Инфраструктурный слой для управления service-to-service коммуникацией в микросервисной архитектуре.

**Примеры:**
- Istio
- Linkerd
- Consul Connect

**Функции:**
- Traffic management
- Security (mTLS)
- Observability
- Policy enforcement

#### 2. Storage Networks

**Описание:**
Специализированные виртуальные сети для storage трафика.

**Характеристики:**
- Изоляция от data traffic
- Оптимизация для block/file storage
- Поддержка iSCSI, NFS, FC over Ethernet

**Применение:**
- SAN (Storage Area Networks)
- Distributed storage (Ceph, GlusterFS)
- Backup networks

#### 3. Management Networks

**Описание:**
Выделенные сети для управления инфраструктурой.

**Применение:**
- Out-of-band management
- Hypervisor management
- Monitoring и logging
- Backup и disaster recovery

# Что такое контейнер?

## Краткий ответ

Контейнер — это стандартизированная единица программного обеспечения, которая упаковывает код приложения вместе со всеми его зависимостями (библиотеки, файлы конфигурации, среда выполнения) в единый образ. Контейнер представляет собой изолированный процесс (или группу процессов) на хост-системе, который использует общее ядро ОС, но имеет собственное файловое пространство, сетевой стек и ресурсы.

## Развёрнутый ответ

### Определение

Контейнер — это легковесная, автономная, исполняемая единица программного обеспечения, которая включает все необходимое для запуска приложения: код, среду выполнения, системные инструменты, библиотеки и настройки. Контейнер работает как изолированный процесс в пользовательском пространстве операционной системы.

### Структура контейнера

**Образ контейнера**: Контейнер создается из образа (image) — неизменяемого шаблона, содержащего файловую систему и метаданные. Образ состоит из слоев, каждый из которых представляет изменения файловой системы.

**Время выполнения**: При запуске образ становится контейнером — работающим процессом с собственным изолированным окружением. Контейнер добавляет поверх только для чтения слоев образа записываемый слой.

**Изоляция**: Контейнер изолирован от других контейнеров и хост-системы через механизмы ядра:
- **PID namespace** — изоляция процессов
- **Network namespace** — изоляция сетевого стека
- **Mount namespace** — изоляция точек монтирования
- **IPC namespace** — изоляция межпроцессного взаимодействия
- **UTS namespace** — изоляция hostname и domainname
- **User namespace** — изоляция пользователей и групп

### Характеристики контейнера

**Легковесность**: Контейнеры разделяют ядро хост-системы, не требуя полной копии операционной системы. Типичный контейнер занимает десятки мегабайт и запускается за секунды, в отличие от виртуальных машин, которые занимают гигабайты и запускаются минутами.

**Изоляция ресурсов**: Через cgroups контейнер получает гарантированные и ограниченные ресурсы:
- CPU (количество ядер, доли процессорного времени)
- Память (лимиты RAM и swap)
- Дисковый I/O (приоритеты и лимиты)
- Сеть (bandwidth control)

**Портативность**: Контейнер работает одинаково на любой системе с поддержкой контейнерного движка — локальная машина, сервер в дата-центре, облако. Принцип "build once, run anywhere".

**Иммутабельность**: Образы контейнеров неизменяемы. Все изменения во время работы происходят во временном записываемом слое и могут быть отброшены при пересоздании контейнера.

### Жизненный цикл

1. **Created** — контейнер создан, но не запущен
2. **Running** — контейнер выполняется
3. **Paused** — процессы контейнера приостановлены
4. **Stopped** — контейнер остановлен, но сохранен
5. **Deleted** — контейнер удален

### Типы контейнеров

**Системные контейнеры**: Запускают полноценную операционную систему с init-системой (LXC, LXD). Ведут себя подобно виртуальным машинам.

**Прикладные контейнеры**: Запускают одно приложение или сервис (Docker, containerd). Это наиболее распространенный подход.

### Практическое применение

Контейнеры используются для:
- Изоляции приложений и их зависимостей
- Обеспечения согласованности между окружениями разработки, тестирования и продакшена
- Быстрого масштабирования приложений
- Эффективного использования ресурсов сервера
- Упрощения развертывания и отката версий

### Отличия от процессов и виртуальных машин

**От обычного процесса**: Контейнер обеспечивает строгую изоляцию, собственное файловое пространство и гарантированные ресурсы.

**От виртуальной машины**: Контейнер не эмулирует аппаратное обеспечение, не содержит гостевую ОС, быстрее запускается и требует меньше ресурсов.

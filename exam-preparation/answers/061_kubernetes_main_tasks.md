# Основные задачи Kubernetes

## Краткий ответ
Основные задачи Kubernetes включают: **оркестрацию контейнеров** (автоматическое размещение и масштабирование), **управление жизненным циклом приложений** (развёртывание, обновление, откат), **обеспечение высокой доступности** (самовосстановление, репликация), **управление ресурсами** (изоляция, квоты, лимиты) и **сетевое взаимодействие** (Service Discovery, балансировка нагрузки). Kubernetes автоматизирует операционные задачи контейнерного управления.

## Развёрнутый ответ

### 1. Оркестрация и планирование контейнеров

**Автоматическое размещение (Scheduling)**
- Интеллектуальное распределение Pod по узлам кластера
- Учёт требований к ресурсам (CPU, память, диск)
- Оптимизация использования инфраструктуры
- Соблюдение ограничений и предпочтений размещения (affinity, anti-affinity, taints, tolerations)

**Bin Packing**
- Максимально эффективное использование ресурсов узлов
- Размещение контейнеров на основе их требований к ресурсам
- Уменьшение количества необходимых узлов

**Примеры:**
```yaml
# Требования к ресурсам
resources:
  requests:
    cpu: 100m
    memory: 128Mi
  limits:
    cpu: 500m
    memory: 512Mi

# Node Affinity для размещения на определённых узлах
affinity:
  nodeAffinity:
    requiredDuringSchedulingIgnoredDuringExecution:
      nodeSelectorTerms:
      - matchExpressions:
        - key: disktype
          operator: In
          values:
          - ssd
```

### 2. Автоматическое масштабирование

**Horizontal Pod Autoscaling (HPA)**
- Автоматическое изменение количества Pod на основе метрик
- Масштабирование по CPU, памяти или кастомным метрикам
- Поддержка multiple метрик одновременно

**Vertical Pod Autoscaling (VPA)**
- Автоматическая корректировка requests и limits ресурсов
- Оптимизация использования ресурсов для каждого Pod

**Cluster Autoscaling**
- Автоматическое добавление/удаление узлов кластера
- Интеграция с облачными провайдерами
- Оптимизация затрат на инфраструктуру

**Пример HPA:**
```yaml
apiVersion: autoscaling/v2
kind: HorizontalPodAutoscaler
metadata:
  name: app-hpa
spec:
  scaleTargetRef:
    apiVersion: apps/v1
    kind: Deployment
    name: app
  minReplicas: 2
  maxReplicas: 10
  metrics:
  - type: Resource
    resource:
      name: cpu
      target:
        type: Utilization
        averageUtilization: 70
```

### 3. Управление жизненным циклом приложений

**Декларативное управление**
- Описание желаемого состояния системы
- Автоматическое приведение к желаемому состоянию
- Версионирование конфигураций

**Развёртывание (Deployment)**
- Управление обновлениями приложений
- Стратегии развёртывания (Rolling Update, Recreate)
- Контроль процесса обновления
- Pause/Resume развёртывания

**Откат (Rollback)**
- Быстрый возврат к предыдущей версии
- История ревизий развёртываний
- Автоматический откат при ошибках (с помощью дополнительных инструментов)

**StatefulSet для Stateful приложений**
- Стабильные сетевые идентификаторы
- Упорядоченное развёртывание и масштабирование
- Постоянное хранилище с привязкой к Pod

### 4. Самовосстановление и высокая доступность

**Автоматический перезапуск контейнеров**
- Мониторинг состояния контейнеров
- Перезапуск упавших контейнеров
- Liveness probes для определения "живых" контейнеров

**Замена и перепланирование Pod**
- Автоматическое создание новых Pod взамен упавших
- Перепланирование Pod на здоровые узлы при сбое узла
- Поддержание заданного количества реплик

**Readiness проверки**
- Контроль готовности Pod к обработке трафика
- Исключение не готовых Pod из балансировки
- Предотвращение отправки трафика на неготовые экземпляры

**Пример проверок:**
```yaml
livenessProbe:
  httpGet:
    path: /healthz
    port: 8080
  initialDelaySeconds: 3
  periodSeconds: 3

readinessProbe:
  httpGet:
    path: /ready
    port: 8080
  initialDelaySeconds: 5
  periodSeconds: 5
```

### 5. Service Discovery и балансировка нагрузки

**Обнаружение сервисов**
- Автоматическое создание DNS записей для Service
- Переменные окружения с информацией о Service
- Стабильные точки входа для динамических Pod

**Балансировка нагрузки**
- Автоматическое распределение трафика между Pod
- Поддержка различных типов Service
- Интеграция с внешними балансировщиками (LoadBalancer type)

**Ingress для HTTP/HTTPS**
- Маршрутизация на основе URL
- SSL/TLS терминация
- Name-based virtual hosting

### 6. Управление конфигурацией и секретами

**ConfigMaps**
- Хранение конфигурации приложений
- Отделение конфигурации от кода
- Возможность изменения конфигурации без пересборки образов

**Secrets**
- Безопасное хранение чувствительных данных
- Пароли, токены, ключи
- Шифрование в etcd (при настройке)

**Пример использования:**
```yaml
# ConfigMap
apiVersion: v1
kind: ConfigMap
metadata:
  name: app-config
data:
  app.properties: |
    key=value

# Использование в Pod
env:
- name: CONFIG_KEY
  valueFrom:
    configMapKeyRef:
      name: app-config
      key: app.properties
```

### 7. Управление хранилищем

**Volumes**
- Абстракция над различными типами хранилищ
- Постоянное хранение данных
- Разделение данных между контейнерами в Pod

**Persistent Volumes (PV) и Persistent Volume Claims (PVC)**
- Динамическое выделение хранилища
- Независимость приложений от деталей реализации хранилища
- Storage Classes для различных типов хранилищ

**Volume Snapshots**
- Создание снимков данных
- Восстановление из снимков
- Миграция данных

### 8. Управление ресурсами и изоляция

**Resource Requests и Limits**
- Гарантированные ресурсы (requests)
- Ограничения использования (limits)
- Предотвращение monopolization ресурсов

**Quality of Service (QoS) классы**
- **Guaranteed**: requests = limits
- **Burstable**: requests < limits
- **BestEffort**: без requests/limits

**Namespaces**
- Логическая изоляция ресурсов
- Разделение кластера между командами/проектами
- Применение политик и квот на уровне namespace

**Resource Quotas**
- Ограничение использования ресурсов в namespace
- Контроль количества объектов
- Предотвращение чрезмерного потребления ресурсов

### 9. Сетевая изоляция и безопасность

**Network Policies**
- Контроль сетевого трафика между Pod
- Правила ingress/egress
- Микросегментация сети

**RBAC (Role-Based Access Control)**
- Контроль доступа к ресурсам API
- Роли и привязки ролей
- Принцип наименьших привилегий

**Pod Security Standards**
- Определение политик безопасности для Pod
- Три уровня: Privileged, Baseline, Restricted
- Предотвращение запуска небезопасных конфигураций

### 10. Мониторинг и логирование

**Metrics Server**
- Сбор метрик использования ресурсов
- Основа для автомасштабирования
- Команды kubectl top

**Интеграция с системами мониторинга**
- Prometheus для сбора метрик
- Grafana для визуализации
- Alertmanager для уведомлений

**Централизованное логирование**
- Агрегация логов контейнеров
- EFK/ELK стеки
- Трейсинг распределённых систем

### 11. Batch задачи и задачи по расписанию

**Jobs**
- Выполнение одноразовых задач
- Гарантия успешного завершения
- Параллельное выполнение задач

**CronJobs**
- Задачи по расписанию (как Unix cron)
- Периодические операции обслуживания
- Backup и cleanup задачи

### 12. Поддержка различных типов рабочих нагрузок

**Stateless приложения**
- Веб-серверы, API
- Легко масштабируемые
- Deployments

**Stateful приложения**
- Базы данных
- Очереди сообщений
- StatefulSets

**Демоны**
- Мониторинг агенты
- Сетевые плагины
- DaemonSets

**Batch обработка**
- Обработка данных
- ETL процессы
- Jobs и CronJobs

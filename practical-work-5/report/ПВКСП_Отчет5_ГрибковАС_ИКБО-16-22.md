::: {custom-style="Heading 2"}
Kubernetes
:::

::: {custom-style="Normal"}
Kubernetes — это открытая платформа для автоматизации развертывания, масштабирования и управления контейнеризированными приложениями. Kubernetes группирует контейнеры, составляющие приложение, в логические единицы для упрощения управления и обнаружения.

Основные компоненты архитектуры Kubernetes:

- **Control Plane** — управляющий слой кластера, отвечающий за принятие глобальных решений о кластере и обнаружение событий кластера.
- **Nodes** — рабочие узлы кластера, на которых выполняются контейнеризированные приложения.
- **Pods** — минимальная развертываемая единица в Kubernetes, представляющая один или несколько контейнеров.
- **Deployments** — описывают желаемое состояние приложения и управляют созданием и обновлением Pods.
- **Services** — абстракция, определяющая логический набор Pods и политику доступа к ним.
:::

::: {custom-style="Heading 2"}
Minikube
:::

::: {custom-style="Normal"}
Minikube — это инструмент для локального запуска Kubernetes. Minikube запускает однузловой кластер Kubernetes на локальном компьютере для пользователей, желающих изучить Kubernetes или разрабатывать приложения локально.

Основные возможности Minikube:

- Поддержка нескольких драйверов виртуализации (Docker, VirtualBox, KVM и др.)
- Поддержка Kubernetes dashboard
- Работа с различными версиями Kubernetes
- Поддержка дополнений (addons) для расширения функциональности
- Локальный реестр Docker для использования собственных образов
:::

::: {custom-style="Heading 2"}
kubectl
:::

::: {custom-style="Normal"}
kubectl — это инструмент командной строки для взаимодействия с кластером Kubernetes. Он позволяет запускать команды для управления кластером, развертывания приложений, проверки и управления ресурсами кластера, а также просмотра логов.

Основные группы команд kubectl:

- Управление ресурсами (create, apply, delete)
- Просмотр информации о ресурсах (get, describe)
- Работа с приложениями (scale, expose, rollout)
- Отладка и диагностика (logs, exec, port-forward)
:::

::: {custom-style="Heading 2"}
Pod
:::

::: {custom-style="Normal"}
Pod — это наименьшая развертываемая единица в Kubernetes, которая может быть создана и управляема. Pod представляет собой группу из одного или нескольких контейнеров со shared storage и network ресурсами, а также спецификацией по запуску контейнеров.

Характеристики Pod:

- Все контейнеры в Pod разделяют IP-адрес и порты
- Контейнеры в Pod могут обмениваться данными через localhost
- Pod эфемерны — они могут быть созданы и уничтожены по мере необходимости
- Обычно Pod управляется контроллерами высокого уровня (например, Deployment)
:::

::: {custom-style="Heading 2"}
Deployment
:::

::: {custom-style="Normal"}
Deployment — это объект Kubernetes, который описывает желаемое состояние приложения. Deployment управляет созданием и обновлением экземпляров приложения (Pods) и обеспечивает декларативное обновление приложений.

Основные функции Deployment:

- Автоматическое создание и масштабирование Pods
- Откат к предыдущим версиям приложения
- Rolling updates — обновление приложений без простоя
- Самовосстановление — автоматический перезапуск неисправных Pods
:::

::: {custom-style="Heading 2"}
Service
:::

::: {custom-style="Normal"}
Service — это абстракция, которая определяет логический набор Pods и политику доступа к ним. Service обеспечивает стабильную сетевую точку входа для доступа к динамическому набору Pods.

Типы Service:

- **ClusterIP** — предоставляет доступ к Service только внутри кластера
- **NodePort** — открывает Service на указанном порту каждого узла кластера
- **LoadBalancer** — создает внешний балансировщик нагрузки
- **ExternalName** — отображает Service на DNS-имя
:::

Назовите виды контроллеров в Kubernetes
:::

::: {custom-style="Normal"}
Контроллеры в Kubernetes — это управляющие циклы, которые отслеживают состояние кластера и при необходимости вносят изменения для достижения желаемого состояния.

Основные виды контроллеров:

1. **ReplicaSet** — обеспечивает поддержание указанного количества реплик Pods. Гарантирует, что определенное число идентичных Pods всегда запущено.

2. **Deployment** — предоставляет декларативные обновления для Pods и ReplicaSets. Управляет развертыванием новых версий приложений с возможностью отката.

3. **StatefulSet** — управляет развертыванием и масштабированием набора Pods с гарантией упорядоченности и уникальности. Используется для stateful приложений, таких как базы данных.

4. **DaemonSet** — обеспечивает запуск одной копии Pod на каждом узле кластера. Используется для системных сервисов, таких как сборщики логов или мониторинг.

5. **Job** — создает один или несколько Pods и обеспечивает успешное завершение указанного количества из них. Используется для пакетных задач.

6. **CronJob** — создает Jobs по расписанию, подобно cron в Unix-системах.

7. **ReplicationController** — устаревший контроллер, предшественник ReplicaSet. Гарантирует запуск указанного числа реплик Pods.
:::

::: {custom-style="Heading 2"}
Как называется командная строка в Kubernetes?
:::

::: {custom-style="Normal"}
Командная строка в Kubernetes называется **kubectl** (произносится как "cube-control" или "cube-cuttle").

kubectl — это интерфейс командной строки для выполнения команд в кластерах Kubernetes. Он позволяет разворачивать приложения, проверять и управлять ресурсами кластера, просматривать логи и выполнять другие операции.

Основные возможности kubectl:

- Управление ресурсами (create, apply, delete, edit)
- Просмотр информации о ресурсах (get, describe, logs)
- Масштабирование приложений (scale)
- Обновление приложений (rollout)
- Отладка (exec, port-forward, attach)
- Управление конфигурацией (config)

kubectl взаимодействует с Kubernetes API сервером для выполнения операций в кластере. Конфигурация kubectl хранится в файле kubeconfig, который содержит информацию о кластерах, пользователях и контекстах.
:::

::: {custom-style="Heading 2"}
Что такое под?
:::

::: {custom-style="Normal"}
**Pod (под)** — это наименьшая и простейшая единица развертывания в Kubernetes, которая может быть создана и управляема.

Основные характеристики Pod:

1. **Группа контейнеров** — Pod может содержать один или несколько контейнеров, которые тесно связаны и должны работать вместе. Контейнеры в одном Pod разделяют общие ресурсы.

2. **Общая сеть** — все контейнеры в Pod разделяют один сетевой namespace, включая IP-адрес и порты. Контейнеры могут общаться друг с другом через localhost.

3. **Общее хранилище** — контейнеры в Pod могут использовать общие volumes для обмена данными.

4. **Эфемерность** — Pods являются эфемерными объектами. Они могут быть созданы, уничтожены и пересозданы по мере необходимости. При пересоздании Pod получает новый IP-адрес.

5. **Атомарность** — Pod является атомарной единицей планирования. Все контейнеры в Pod всегда размещаются на одном узле кластера.

6. **Жизненный цикл** — Pod проходит через различные фазы: Pending, Running, Succeeded, Failed, Unknown.

Pods обычно не создаются пользователями напрямую. Вместо этого используются контроллеры высокого уровня, такие как Deployment, которые управляют созданием и жизненным циклом Pods.
:::

::: {custom-style="Heading 2"}
Назовите 2 типа ресурсов, из которых состоит кластер Kubernetes
:::

::: {custom-style="Normal"}
Кластер Kubernetes состоит из двух основных типов ресурсов:

1. **Control Plane (Master Node)** — управляющий слой кластера, который принимает глобальные решения о кластере и обнаруживает события кластера.

Компоненты Control Plane:

- **kube-apiserver** — предоставляет Kubernetes API, является фронтендом для Control Plane. Все операции в кластере проходят через API сервер.

- **etcd** — распределенное key-value хранилище для хранения всех данных кластера, включая конфигурацию, состояние и метаданные.

- **kube-scheduler** — отслеживает вновь созданные Pods без назначенного узла и выбирает узел для их запуска на основе требований к ресурсам.

- **kube-controller-manager** — запускает процессы-контроллеры, которые регулируют состояние кластера (Node Controller, ReplicaSet Controller, Endpoints Controller и др.).

- **cloud-controller-manager** — взаимодействует с облачными провайдерами для управления облачными ресурсами.

2. **Worker Nodes (Node)** — рабочие узлы кластера, на которых выполняются контейнеризированные приложения.

Компоненты Worker Node:

- **kubelet** — агент, который выполняется на каждом узле кластера. Обеспечивает запуск контейнеров в Pods и следит за их работоспособностью.

- **kube-proxy** — сетевой прокси, который поддерживает сетевые правила на узлах. Реализует сетевую модель Service.

- **Container Runtime** — программное обеспечение для запуска контейнеров (Docker, containerd, CRI-O и др.).

Control Plane управляет Worker Nodes и Pods в кластере. В production-среде Control Plane обычно работает на нескольких узлах для обеспечения отказоустойчивости, а Worker Nodes выполняют приложения.
:::

::: {custom-style="Heading 2"}
Чем Kubernetes отличается от Docker Swarm?
:::

::: {custom-style="Normal"}
Kubernetes и Docker Swarm — это две системы оркестрации контейнеров, но они имеют существенные различия:

**1. Сложность и кривая обучения**

Docker Swarm проще в освоении и настройке. Он интегрирован в Docker и использует знакомый интерфейс командной строки Docker. Kubernetes имеет более крутую кривую обучения из-за большего количества концепций и возможностей.

**2. Масштабируемость**

Kubernetes разработан для работы с очень большими кластерами (тысячи узлов) и обеспечивает более эффективное масштабирование. Docker Swarm лучше подходит для кластеров малого и среднего размера.

**3. Функциональность**

Kubernetes предоставляет значительно больше функций: автоматическое масштабирование (Horizontal Pod Autoscaler), более гибкое управление сетями, поддержка различных типов хранилищ, встроенная система мониторинга и логирования. Docker Swarm предоставляет базовые функции оркестрации.

**4. Доступность и отказоустойчивость**

Kubernetes имеет более продвинутые механизмы обеспечения высокой доступности, включая автоматическое перемещение Pods при сбоях узлов, health checks, self-healing. Docker Swarm также обеспечивает отказоустойчивость, но с меньшими возможностями настройки.

**5. Экосистема**

Kubernetes имеет обширную экосистему инструментов и поддержку всех основных облачных провайдеров (Google Kubernetes Engine, Amazon EKS, Azure AKS). Docker Swarm имеет меньшую экосистему и поддержку.

**6. Развертывание приложений**

Kubernetes использует декларативный подход с манифестами YAML, поддерживает сложные стратегии развертывания (rolling updates, blue-green, canary). Docker Swarm использует Docker Compose файлы и более простые стратегии развертывания.

**7. Сетевая модель**

Kubernetes использует CNI (Container Network Interface) и поддерживает различные сетевые плагины. Docker Swarm использует встроенную overlay-сеть, которая проще в настройке, но менее гибкая.

**8. Сообщество и поддержка**

Kubernetes имеет большое активное сообщество, регулярные обновления и поддержку от Cloud Native Computing Foundation. Docker Swarm имеет меньшее сообщество и более медленное развитие.

**Выбор между Kubernetes и Docker Swarm:**

Docker Swarm подходит для небольших проектов, когда требуется быстрое развертывание и простота управления. Kubernetes является лучшим выбором для enterprise-приложений, требующих высокой масштабируемости, гибкости и продвинутых возможностей оркестрации.
